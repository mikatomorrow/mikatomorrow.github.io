Hyundai Motors Lab — IONIQ 6 L2/L3 HMI & Driving Simulator

Senior Capstone  |  Spring 2025  |  ID|EE|CMPE: L2/L3 Interface Design — Hyundai HATCI
w/ Clarissa Kim, Edmond Li, Xiaoyang Wang, Adam Whitney, Cynthia Zhou

★ Best ECE Project — Georgia Tech Capstone Expo 2025

Overview

Cross-disciplinary capstone project for Hyundai’s Advanced Technology Center (HATCI), investigating how to improve driver trust and confidence in the IONIQ 6’s Highway Driving Assist 2.0 (HDA 2.0) system within semi-Level 2 and emerging Level 2+ ADAS contexts. The project delivered three major bodies of work: (1) a validated HMI confidence metric, (2) a redesigned HDA 2.0 user interface, and (3) a physical + virtual driving simulator for ongoing Hyundai research.

My contributions (Simulator subteam lead): Physical rig construction and iteration — 3D-printed IONIQ 6 steering wheel sleeve, dual 12.3″ display mount, surround-sound integration. Unreal Engine 5.4 virtual environment — ADAS functionality blueprints (Smart Cruise Control, Lane Keeping Assist, HDA, Lane Following Assist, distance tracking), map development from infinite highway → 1:1 Google Earth route → CityScape HD. Simulator-to-car correlation analysis (r = 0.63 Pearson).

Simulator Rig

Physical Rig

The physical rig provides a 1:1 IONIQ 6 cockpit experience for controlled HMI testing and biometric data collection:

  • Steering wheel: Logitech G29 base with 3D-printed 14.5″ diameter sleeve matching IONIQ 6 geometry; buttons re-labeled with IONIQ 6 symbols
  • Displays: Dual 12.3″ LCD screens mounted behind the wheel at IONIQ 6-accurate positioning (32–38.5″ from headrest); display the simulated instrument cluster and center console UI
  • Seat: Adjustable to fit 5th–95th percentile (height range ≥2σ from national average)
  • Surround sound: Speaker system added for environmental realism
  • Future upgrade: Two-axis NLR motion platform to be integrated

Virtual Environment (Unreal Engine 5.4)

The virtual environment evolved across three map iterations:

  1. Infinite highway — base map for Phase 1 ADAS functionality testing (LKA, SCC)
  2. 1:1 Google Earth rendering of the actual I-95 test route used in real-car phase 1 testing, including surrounding buildings and infrastructure
  3. CityScape HD map — high-definition plugin-generated environment with autonomous vehicle mesh actors for advanced scenario testing (crowded highway, driver-truck interaction, aggressive drivers)

ADAS functionality blueprints implemented in Unreal Engine:

  • Smart Cruise Control (target-speed throttle control)
  • Lane Keeping Assist (spline-based steering via FindNearestSpline())
  • Highway Driving Assist (HDA)
  • Lane Following Assist
  • Forward distance tracking (SetDistance function)

All ADAS features execute within 500 ms of button press; UIs imported from Figma directly into UE blueprint blocks.

Simulator Validation

Phase 1 compared user behavior between the physical IONIQ 6 and the simulator rig using a multi-variable correlation metric (confidence score, UX self-report, pupil size, HRV/RMSSD, task time). A paired-sample t-test on z-score-weighted composite scores yielded:

Pearson r = 0.63  (simulator vs. real-car composite scores)

This confirmed the simulator as a valid surrogate for real-vehicle HMI testing, with statistically significant differences in confidence score (p = 0.022) and UX self-report (p = 0.049) between environments.

Confidence Metric

A novel driver confidence metric was developed to quantify trust per user per UI per task. The final formula:

C = 100 · (1 − (α·HRV/HRVₘₐₓ + β·HRᵉᵉᵊ/HRₘₐₓ + γ·ECGᵥₐˇ/ECGₘₐₓ + δ·T + ε·LS/T + ξ·FS + η·SS))

Parameters: HRV (heart rate variability), HRᵉᵉᵊ (deviation from baseline HR), ECGᵥₐˇ (ECG variance), T (normalized task duration), LS/T (gaze-on-screen ratio), FS (facial emotion recognition score), SS (survey score). Implemented in Python; ECG sampled at 130 Hz (ECGLogger), eye tracking at 100 FPS (Tobii Pro Glasses 2), BPM from Polar Beats.

UI A/B/C Testing & Results

Three HMI prototypes were tested within-subjects in randomized order: White UI (baseline IONIQ 6), Green UI, and Blue UI. The Green and Blue UIs encoded different mental models for how ADAS feature icons communicate system state.

UI Icon logic P011 P013 P007 P014
Green UI Icons appear only when feature is toggled on; green = active, gray = on but conditions unmet 36.66 39.15 37.73 41.28
Blue UI Icons always visible when feature is on; separate indicator for activation status 35.35 28.39 4.05 31.33
White UI (baseline) Existing IONIQ 6 production HMI 22.10 0 8.78 0

The Green UI consistently ranked first across all participants, exceeding the 10% relative improvement threshold over baseline in every case. A post-test iteration changed “white” icons (on but inactive) to gray to eliminate the observed confusion between on-but-waiting and fully-active states.

North Star Concept (Level 2+)

A forward-looking design concept for SAE Level 2+ scenarios: a fixed display embedded in the steering wheel hub (screen stays stationary as the wheel turns, co-located with the airbag) provides essential information at the driver’s point of contact. The main display is simplified to essential data during manual control; during HDA handoff, the wheel display shows transition status while the center screen visualizes vehicle systems. Designed for compatibility with Apple CarPlay iOS 16 full-width widget interface.
